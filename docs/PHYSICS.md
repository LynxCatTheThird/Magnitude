# 尺寸、碰撞与地形接触

Magnitude 提供服务端尺寸、姿态与接触能力，供玩法模组扩展。尺寸由有限连续值表示，49.5 等非整数倍率与整数倍率使用相同公式。方块网格、材料硬度和预算可能使实际结果出现离散变化，不存在按 5／10／50 倍选择玩法等级的规则。

## 身体与移动

站立和蹲伏玩家使用头、躯干、双臂、双腿六个定向盒。部位按模型实际倍率定位，不随原版包围盒代理压缩；查询分别覆盖每个部位的扫掠范围，避免把腿间空隙当作实心身体。模型系数已包含原版尺寸属性，蹲伏只应用一次姿态高度比例。

连续 SAT 扫掠、轴向裁剪、台阶试探与服务端新增穿透校验使用这些部位。自动步高为 `min(4.8, 0.6 × BASE)`，抬升、水平移动和落下均须通过碰撞验证；独立于其他模组修改的原版步高属性。这是有界移动辅助，不是腿长或肌肉能力的完整模拟。

起跳在客户端和服务端限速。初始世界竖直位移上限为 `0.42 × sqrt(min(BASE, 100))`，最高 4.2 格/刻；内部速度除以大于一的运动系数，避免位移再次缩放后失控。后续飞行、重力和外部模组加速仍遵循各自规则。

原版包围盒保留动态局部代理，初始限制因子 8，最大 32；扩张前验证加载范围与空闲空间。游泳、滑翔、骑乘、窒息、流体、原版攻击/投射物命中、挤压和部分方块回调仍使用原版包围盒。关节旋转与朝向变化还没有完整连续刚体求解。六部位是简化人体几何，不能自动适配任意资源包模型。

## 接触与方块作用

统一服务端事件记录起跳、空中、落地、尺寸变化、步幅、支撑变化与障碍接触。同一事件先认领再结算，不能重放副作用。地形写入须同时开启服务器与个人 terrain 许可，且玩家具备建造权限。

行走及下落中的撞击只处理双腿实际接触的方块，可破坏硬度随尺寸与水平位移连续增加。每次至多保留 256 个已确认接触；未检查部分不授予通行。先确认有界接触并结算，再由移动求解器读取变更后的世界；全身查询失败仍拒绝移动，但不会阻止已确认接触的分批破坏。无阻挡碰撞的植物/蜘蛛网可通过轮廓形状确认接触，仍不把轮廓当作移动障碍。下一次运动可继续处理剩余障碍。

脚印使用与简化小腿相同横截面的定向矩形，按矩形与方块的实际重叠生成，不是皮肤网格逐像素映射。半宽和半长均为模型宽度系数的0.09倍。步行/起跳硬度阈值为 `min(128, max(0, BASE-1) × 0.75)`；静压为 `min(128, BASE/pressureHardnessFactor)`。步态相位与落脚使用同一条真实模型步距公式：`max(0.4, modelHeight × 0.72 × sin(0.65))`，由简化腿长与摆角估算。行走只在步距完成时结算当前支撑脚，移动中的支撑变化不施加静压，停止后恢复静态承重。步距不再按原版代理封顶。普通单层印记等待双腿实际离开接触面后结算，承重时整片地面保留；没有中心柱例外，释放后统一处理原接触层；同一支撑与尺寸不重复向下开采。

落地由空中到接地过渡、实际位移/下降速度和落差判定，不依赖记忆的跳跃按键。脚掌硬度阈值随下降速度增加，破坏深度由尺寸与速度计算，最多四层。它是有界材料响应，未实现建筑结构支撑分析或倒塌。

每玩家最多保存四个脚印任务，使用固定内存的扫描游标，逐刻共享读写配额；每批最多访问 2048 个候选位置。任务最多存活 100 刻。尺寸/维度变化、移动过远、许可撤回等使任务取消；预算不足则延后。每次写入重新检查当前方块、加载状态、世界边界、容器、流体、保护标签、原版交互权限和 Fabric 保护 veto。不会强制加载区块或主动生成碎屑实体。

## 工作配额与诊断

每次身体查询最多 131072 个潜在单元，每玩家每刻最多 262144 个单元、65536 对检测。两侧各自在游戏线程共享每刻 524288 个单元、524288 对检测；实体候选查询另有每刻 128 次、2048 个候选的配额。最多保存 1024 个障碍盒，每个部位查询检查至多 16 个已加载区块。

空空间也计入预算。碰撞查询不足或区块未知时停止未经验证的移动，不缩小实际身体。极大尺寸或密集场景可能停顿，现有方案没有消除所有规模限制；脚印可分批处理不代表任意巨型身体都能流畅移动。长期世界性能与多人延迟仍需实测。

`/magnitude physics enable` 开启个人地形和压力许可；管理员执行时也开启服务器两项开关。`disable` 对应关闭。`status` 显示双开关、步高、姿态、最近接触、待处理脚印和剩余预算。精细控制用 `physics player terrain|pressure on|off`、管理员 `physics server terrain|pressure on|off`；管理员 `physics reload` 重读配置。

默认尺寸范围为 1/64..32，服务器可在 `config/magnitude.json` 将 minimum/maximum 扩大到 2⁻²⁰..2³²。尺寸存量按运行时可表示的浮点差结算，无法守恒的转移会拒绝。

## 扩展接口

`Dimensions.snapshot` 提供不可变尺寸快照，已继承 BASE 的运动/攻击等系数不能再次乘同一尺寸。接触检测通过 `ContactEvents` 与 `ContactEventBus` 统一派发，事实携带尺寸、位置、速度、姿态、支撑及已确认障碍；目前尚无独立的第三方材料策略注册接口。原始计划与调查记录放在本地研究目录。

姿态适配器在初始化时调用 `BodyPoses.register(Identifier, Adapter)`，在服务器线程以 `BodyPoses.select(ServerPlayer, Identifier)` 选择，null 恢复规范姿态。选择在加载/重生时清除。适配器须保持规范动作 ID 和开始 tick，支撑位 1/2/3 分别表示左脚/右脚/双脚；支撑腿角须接近零，关节角有限且在 ±1.2 radians 内。无效返回、异常或新增穿透会回退。客户端资源本身不能声明服务端物理事实。

自身脚下写入记录支撑丢失来源，阻止同一位置下落后重复落地挖掘及更深静压；腿部障碍扫描排除脚底支撑层。主动起跳、明确上升或移动超过一个步距后重置该来源。任务在空中继续写历史脚印不会再次把当前腾空标记为失去支撑。

姿态切换失败时保留旧几何对应的实际支撑腿，不能仅套用新姿态的支撑位。姿态终点校验只查询实际变化的部位。`status`中的serverTickMs是服务器平均刻耗时；moveAvgMs/moveMaxMs是服务端最近至多128次运动查询耗时，moveDenied为拒绝次数/样本数，lastFailure为最近查询失败原因（可能属于姿态或位置校验，不一定是当前移动）。这些值不测客户端帧时间。

普通单层脚印（包括单层起跳/轻落地结果）保存受力时的固定接触面；实际腿部仍与该面接触时暂缓写入。离开或充分抬脚后再按原位置分批写入，不移动玩家或制造虚拟碰撞地板。等待的任务轮转，避免挡住已卸载任务；缓存只依赖位置、姿态、朝向和尺寸版本，等待期间不逐方块查询。多层落地冲击可即时产生真实下沉，仍受自身支撑丢失防循环规则约束。

静止压力目前是有界材料印记，不是质量/接触面积决定的连续土壤压缩；其外观在卸载后显现。受保护、硬度不够或后续变更的块可导致局部保留，这是材料/保护规则，不能为追求统一深度绕过它们。旧印记已成为真实地形，再次走进时仍可能上下坡；本轮避免的是在当前承重脚下实时制造台阶。
