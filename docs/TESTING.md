# Magnitude 试玩步骤

使用 Minecraft 26.3、Fabric Loader 0.20.1、Fabric API 0.165.0+26.3 与 Java 25。双方使用相同的 Magnitude 构建。以下是测试操作与预期行为，不是内部验收报告。

## 1. 尺寸与基本移动

在开阔平地测试 `0.5`、`1`、`2` 倍；再测试本构建边界 `0.25` 和 `4`。走动、跳跃、转身，检查画面与碰撞是否一致。

```text
/magnitude scale 0.5
/magnitude scale 1
/magnitude scale 2
```

被墙挡住的放大请求应拒绝，不能把玩家挤入墙内。`0`、负数及超过本版本范围的倍率应拒绝。普通玩家应无法通过尺寸命令越过管理员权限。

## 2. 携带猪

将自己调到2倍，对准附近的普通猪执行 `/magnitude carry request`。预期猪在身前跟随，自己仍能正常操作。

依次测试走直线、左右转身、停下、蹲伏、低台阶和靠近墙角。目标不能被拖进障碍；无法继续跟随时应退出并安全安置。执行 `/magnitude carry drop` 后，猪应恢复正常重力与原有AI。

携带中的尺寸修改应被拒绝。不要把猪的临时停止AI理解为永久驯服。

## 3. 两名玩家的确认与退出

将携带者调到2倍，目标保持1倍或更小。下面的玩家名需替换为实际名字。

```text
/magnitude carry request 玩家名
```

预期：请求发出后目标仍可自由移动，尚未附着。目标先执行 `/magnitude carry decline` 验证拒绝，再重新请求并执行 `/magnitude carry accept`。

接受后分别从两端观察：目标位于身前，走动／转身后位置一致；目标可以看向其他方向。测试携带者 `drop`，再测试目标 `escape`。玩家原版下车操作也不应让目标永久卡住。

## 4. 拒绝路径

检查以下情况会给出明确反馈，而且不会占住目标：

- 自己抓自己，或尺寸差不足两倍。
- 目标太远、路径有墙、身前没有容纳空间。
- 目标正在被别人携带，或参与者已经占用其他携带关系。
- 玩家没有接受，或请求已过期。
- 对方未安装对应模组。

## 5. 退出、死亡与重新进入

在携带猪和携带玩家时，分别测试目标退出、携带者退出以及正常关闭世界再打开。预期不会恢复未经再次同意的捕获，也不会遗留永久无重力／无敌／停止AI状态。

若出现待安置提示，先移到或清理出附近安全空间，再执行 `/magnitude carry recover`。管理员可用 `/magnitude carry recover <目标>` 协助。不要在有待恢复目标时直接删除模组文件；先完成释放。

## 6. 反馈时提供

请记录模组版本、双方倍率、操作顺序、所在环境、具体提示，以及是否只在一端显示异常。说明问题是“操作被拒绝”“位置回弹”“穿入方块”“退出失败”还是帧率下降。

需要日志时只分享相关片段，先检查其中的账号、服务器地址及其他个人信息。截图能帮助描述外观，但同步与恢复问题还需要操作步骤才能复现。
