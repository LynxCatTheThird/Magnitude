# 碰撞、动画与结构物理计划

## 当前实现

默认尺寸范围为 1/64..32，配置可扩大到 2⁻²⁰..2³²。BASE、模型与眼高保留极端值。0.1.3.1 玩家代理由加载范围和空间遍历预算调整，初始限制因子为 8，每 5 ticks 最多增长 0.25，遇到未验证区域立即收缩；代理最小限制因子 1，微型玩家仍保留真实小尺寸。碰撞宽高分别经代理限幅；其他生物仍使用 8 倍保护。运动上限 8；自动台阶只使用原版 0.6 方块高度，树干、墙体和房屋不能连续当作台阶，交互上限 16，第三人称距离上限 32，掉落物/投射物/爆炸上限 8。

玩家头、躯干、双臂与双腿采用六个内部定向盒，不增加实体。站立/蹲伏移动使用连续 SAT 扫掠和轴向裁剪，台阶试探也用这些形状；工具瞄准及服务端新增穿透校验接入同一模型。关节更新检查终点是否新增方块穿透，失败保留先前有效角度。规范步幅、支撑脚与交替单脚起跳由服务端计算；腾空不施加支撑。客户端接收动作、开始 tick、相位、支撑位、关节角度、代理限制、回退状态与递增版本，在渲染状态提取阶段复制并插值；使用物品/攻击时保留原版手臂动画。

地形作用须开启服务器与个人 terrain 开关。承重由初次支撑、落地、移动到新支撑位置或尺寸变化事件触发，同一支撑位置和尺寸只处理一次；硬度阈值按实际方块破坏硬度与 `size/pressureHardnessFactor` 比较，不再固定为石头范围；保留中央支撑柱防止瞬间陷落，每次处理脚下一层。行走撞击会先尝试破坏正前方障碍，再使用原版半格台阶逻辑。脚印为随骨骼接触位置旋转的椭圆靴面，仍是方块级玩法近似。

当前是局部骨骼代理，不是任意网格的逐三角形碰撞。完整实际尺寸骨骼可通过 `PlayerBody.actualParts` 获取，但移动和破坏只结算有限的局部代理，不遍历全身巨大的世界包围盒。游泳/滑翔/骑乘仍使用原版姿态移动；窒息、流体、原版攻击/投射物命中、挤压和部分方块回调仍依赖原版包围盒。关节旋转尚无完整连续求解，朝向旋转与持物动作也不是严格刚体模拟。建筑倒塌仍未实现。

## 服务端动画适配 API

配套模组在初始化时注册 `BodyPoses.register(Identifier, Adapter)`，在服务器线程以 `BodyPoses.select(ServerPlayer, Identifier)` 选择；传入 null 恢复规范姿态。选择在加载/重生时清除。适配器接收玩家与规范 `BodyPose`，返回同一动作 ID 和开始 tick 的受限关节角度与支撑位；1 表示左脚，2 表示右脚，3 表示双脚。支撑脚腿角必须接近零，角度须有限且在 ±1.2 radians 内，单次变化有界；腾空不能制造支撑，起跳须选择一只脚。无效返回、异常或方块穿透使用规范/上一有效姿态回退。没有服务端接收客户端碰撞声明的通道。

这是可调用的模组 API，还没有数据包物理描述加载器或某个资源包的自动适配器。视觉包与服务器定义不一致时，第三方需要使用同步姿态或提供配套适配逻辑；不能声称自动跟随任意包的动作。

## 为什么不能直接使用任意客户端模型

渲染网格、实体移动碰撞、交互命中与地形接触是不同接口。当前原版移动解析围绕 EntityDimensions/AABB 与方块 VoxelShape 运作；换一个 getDimensions 返回值不能提供旋转的四肢或动画网格碰撞。完整替换还需处理移动裁剪、台阶、落地、窒息、骑乘、实体挤压、流体、命中和服务端位置校正。

动画资源包可能只在客户端计算骨骼，不同客户端还可使用不同资源。渲染插值的每帧姿态也不等于服务端每 tick 的状态。Fresh Animations 作者说明其动画依赖 CEM/EMF，玩家扩展依赖 EMF/ETF；EMF 项目将服务端标为不支持。因此服务器不能直接获得某个玩家当前所见的左右脚相位，也不能直接相信客户端上报的碰撞形状。

主张使用动画模型的简化骨骼碰撞：头与躯干采用定向盒，四肢采用定向盒或胶囊；服务端计算规范姿态，客户端插值显示。精确到每个渲染三角形的碰撞可作特定玩法试验，但不是初始方案。

## 动态代理与预算

代理选取检查最多 16 个区块，不强制加载；二分计算可验证范围，扩张前确认空间空闲且位于世界边界内。候选/空间查询在进入引擎前限额，截断结果明确标为不完整。实际动作扫掠区域先计算体素访问上界，空区域同样计入预算。

每次移动至多 8192 个潜在方块单元；每玩家每 tick 至多 32768 单元和 65536 对检测。两侧各自在游戏线程共享每 tick 131072 单元与 524288 对检测；候选查询另用每 tick 128 次、2048 个候选的预算。最多保存 1024 个障碍盒。预算不足、候选截断或区块缺失时，中止原版移动的后续步骤并清零速度，避免未知区域被当作空气或后续步骤意外加载区块。可能出现短时停顿，需要负载实测后调整策略。

未来工作包括实际全身几何与已加载空间树的局部交集、更多原版接触路径、关节连续旋转、姿态切换/台阶精细化、延迟预测与第三方动画适配。当前局部代理内部也采用简化人体比例，不能将其描述为完整模型碰撞已全部实现。

## 极端尺寸配置

在 `config/magnitude.json` 修改以下字段，保留其他配置，再执行 `/magnitude admin reload`：

```json
{
  "minimum": 0.00000095367431640625,
  "maximum": 4294967296,
  "standingPressure": true
}
```

新安装与已有配置默认保留原范围。随机区间须位于服务器配置内。携带偏移按受限物理尺寸计算；视线检查使用目标物理代理。尺寸存量按实际可表示的浮点差结算，无法守恒的转移会拒绝。

现有 blocksPerTick、checksPerTick、blocksPerImpact、impactRadius 仍限制地形路径。保护 tag、容器、流体、未加载区块、世界边界、原版保护与 Fabric veto 仍适用。模组不主动生成碎屑，但原版邻居更新与第三方行为仍可能产生后续实体或工作。

## 结构倒塌与引擎评估

1. 在已加载区块内作有界支撑搜索，通过 tag 定义材料、锚点、跨距与承重，支持梁、侧向支撑与拱桥。预算耗尽时保持结构，不能将“没查到锚点”当作失去支撑。
2. 任务保存玩家、维度、原方块与结构版本，队列和每任务规模设硬上限，分批读写共享预算。卸载、方块变化、许可撤回或保护 veto 时取消或重验，容器和保护块默认不迁移。
3. 用有限块集或整体碎片结算，避免每方块一个 FallingBlockEntity；限制活动结构、实体数、接触对和存活时间，迁移失败不得复制或吞掉方块。
4. 将承重升级为受限质量/接触面积模型，区分站立、步行、起跳与落地能量，加入下沉和裂纹反馈；明确超过物理代理后的质量规则。
5. 通用引擎只在隔离原型验证 Java 25/Fabric 26.3、专服/客户端同步、碰撞、存档、保护、卸载、故障恢复和许可证后再选择。本轮不新增引擎依赖。

## 验收与证据

已有 197 项服务端回归，覆盖原有功能与六部位移动、薄玻璃、半砖台阶、真实单脚脚印、姿态/协议、动态代理、空区域预算、未加载区域及配额耗尽。有限石头夹具中 1000 次巨型请求未增加碎屑实体。客户端渲染 Mixin 与资源启动通过。尚未验证真实世界 FPS/MSPT、极端客户端观感、第三方动画包或双客户端同步。

新增方案须验证交替单脚起跳、左右脚落地、不同客户端资源包、缺少/不匹配适配器、延迟/丢包、非法姿态、树干/墙体/房屋台阶误判、台阶/斜坡、窄门/薄方块、游泳/骑乘、跨未加载区块及预算耗尽。结构夹具包含单柱、悬臂、拱桥、保护块、容器、多人破坏和重启。以 BASE 1、32、1024、2³² 记录接触误差、位置校正、实体数、空间访问量和 tick 时间 p95/p99，再决定是否替换默认保护。
