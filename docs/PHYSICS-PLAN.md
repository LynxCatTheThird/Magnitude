# 碰撞、动画与结构物理计划

## 当前实现

默认尺寸范围为 1/64..32，配置可扩大到 2⁻²⁰..2³²。BASE、模型与眼高保留极端值；当前碰撞宽高仍限制为标准尺寸的 8 倍，玩家最大物理碰撞箱约 4.8×14.4 方块。运动/台阶因子上限 8，交互因子上限 16，第三人称距离因子上限 32，掉落物/投射物/爆炸继承因子上限 8。

左右脚印按位移累计步幅并随朝向旋转；普通跳跃有起跳破坏与落地冲击；8 倍以上接地玩家每 20 ticks 施加承重。地形作用须同时开启服务器与个人 terrain 开关。站立承重以 `min(8, size/16)` 为硬度阈值，每次处理脚下一层，是玩法近似。

目前脚印不读取动画骨骼，普通跳跃使用双脚接触，不能声称已经跟随动画实现交替单脚起跳。完整模型碰撞、动画适配器、动态物理代理和建筑倒塌均尚未实现。

## 为什么不能直接使用任意客户端模型

渲染网格、实体移动碰撞、交互命中与地形接触是不同接口。当前原版移动解析围绕 EntityDimensions/AABB 与方块 VoxelShape 运作；换一个 getDimensions 返回值不能提供旋转的四肢或动画网格碰撞。完整替换还需处理移动裁剪、台阶、落地、窒息、骑乘、实体挤压、流体、命中和服务端位置校正。

动画资源包可能只在客户端计算骨骼，不同客户端还可使用不同资源。渲染插值的每帧姿态也不等于服务端每 tick 的状态。Fresh Animations 作者说明其动画依赖 CEM/EMF，玩家扩展依赖 EMF/ETF；EMF 项目将服务端标为不支持。因此服务器不能直接获得某个玩家当前所见的左右脚相位，也不能直接相信客户端上报的碰撞形状。

主张使用动画模型的简化骨骼碰撞：头与躯干采用定向盒，四肢采用定向盒或胶囊；服务端计算规范姿态，客户端插值显示。精确到每个渲染三角形的碰撞可作特定玩法试验，但不是初始方案。

## 分阶段实现动画与接触

1. **先完善接触形状。** 保留当前移动代理，先让脚印、承重、践踏与局部命中使用规范的左右脚接触体。只有接地的脚产生支撑或破坏，腾空的脚不计入静态重量。单脚起跳通过规范相位决定，不通过“看到一次跳跃就换脚”猜测动画。
2. **定义服务端姿态协议。** 同步动作 ID、开始 tick、相位、左右脚支撑、朝向与姿态版本；双方使用相同碰撞定义。服务器验证动作状态、允许的关节范围与变化速率。若客户端上报接触，只作为受约束提示，不能扩大范围、绕过遮挡或凭空破坏方块。
3. **明确第三方适配边界。** 对有公开动画状态接口的模组写适配器；资源包须有服务器安装并选定的配套物理描述和动作定义。纯视觉包缺少定义时使用规范姿态回退，不承诺自动支持所有包。数据包可以提供服务器动作/接触定义，但不会自动把客户端骨骼传入服务器。
4. **再试验移动碰撞。** 在有限的骨骼碰撞体集合上处理扫掠碰撞和关节穿透，并接入台阶、蹲伏、游泳、滑翔、骑乘与网络校正。初期控制在六个主要人体部位，限制每实体形状数、每 tick 接触对数和更新频率。没有完成这些接口前不移除当前移动保护。

不要为每个骨骼生成独立实体。规范形状可以作为一个玩家实体的内部碰撞数据存储，降低实体管理与网络开销。

## 替代固定尺寸上限的方案

固定 8 倍上限是当前保护，不是目标方案。单纯提高上限仍会让原版方块/实体空间遍历成本随覆盖范围扩大；候选数量限额也不一定限制遍历空空间的成本。

目标采用“实际尺寸的隐式身体 + 局部精细接触 + 受预算约束的移动代理”：

- 身体用少量规范骨骼形状表达，保留实际缩放；不把巨大外包围盒展开为全部方块或实体分区，也不将整个身体登记到无限多空间单元。
- 查询限定于已加载且正在模拟的区域，通过分区层级或空间树筛掉没有交集的区域，再对附近方块与实体作局部精细检测。除候选数外，同时限制访问的空间单元、方块、接触对和运行时间。
- 姿态与几何用实体局部坐标及双精度计算，接近接触点再转换到世界坐标。精度问题需要独立验证，扩大浮点范围不是解决办法。
- 根部移动代理按当前姿态、加载区域和实际可验证的空间自适应选择；多个活动肢体的接触另行维护。阈值变化采用平滑过渡，避免突然改变碰撞使玩家抖动或穿墙。
- 未加载区域不强制加载。预算不足时保留上次有效支撑并保守限制本次移动，不能把“尚未检查”当作空气；服务器明确同步代理范围与回退状态。

这仍是有限物理模拟。尺寸超出已加载世界时，无法同时保证全身逐块真实碰撞、无限交互范围和固定计算成本。应保留当前可用的保护模式，逐步扩大经验证的局部物理范围。

## 极端尺寸配置

在 `config/magnitude.json` 修改以下字段，保留其他配置，再执行 `/magnitude admin reload`：

```json
{
  "minimum": 0.00000095367431640625,
  "maximum": 4294967296,
  "standingPressure": true
}
```

新安装与已有配置默认保留原范围。随机区间须位于服务器配置内。携带偏移按受限物理尺寸计算；视线检查使用目标物理代理。尺寸存量按实际可表示的浮点差结算，无法守恒的转移会拒绝。

现有 blocksPerTick、checksPerTick、blocksPerImpact、impactRadius 仍限制地形路径。保护 tag、容器、流体、未加载区块、世界边界、原版保护与 Fabric veto 仍适用。模组不主动生成碎屑，但原版邻居更新与第三方行为仍可能产生后续实体或工作。

## 结构倒塌与引擎评估

1. 在已加载区块内作有界支撑搜索，通过 tag 定义材料、锚点、跨距与承重，支持梁、侧向支撑与拱桥。预算耗尽时保持结构，不能将“没查到锚点”当作失去支撑。
2. 任务保存玩家、维度、原方块与结构版本，队列和每任务规模设硬上限，分批读写共享预算。卸载、方块变化、许可撤回或保护 veto 时取消或重验，容器和保护块默认不迁移。
3. 用有限块集或整体碎片结算，避免每方块一个 FallingBlockEntity；限制活动结构、实体数、接触对和存活时间，迁移失败不得复制或吞掉方块。
4. 将承重升级为受限质量/接触面积模型，区分站立、步行、起跳与落地能量，加入下沉和裂纹反馈；明确超过物理代理后的质量规则。
5. 通用引擎只在隔离原型验证 Java 25/Fabric 26.3、专服/客户端同步、碰撞、存档、保护、卸载、故障恢复和许可证后再选择。本轮不新增引擎依赖。

## 验收与证据

已有 151 项服务端回归覆盖极端数值、持久化、当前碰撞保护、脚印、原版移动包跳跃、静止承重与共享预算；有限石头夹具中 1000 次巨型请求未增加碎屑实体。它们没有验证动画骨骼碰撞、动态代理、真实世界 FPS/MSPT、极端客户端观感或双客户端同步。

新增方案须验证交替单脚起跳、左右脚落地、不同客户端资源包、缺少/不匹配适配器、延迟/丢包、非法姿态、台阶/斜坡、窄门/薄方块、游泳/骑乘、跨未加载区块及预算耗尽。结构夹具包含单柱、悬臂、拱桥、保护块、容器、多人破坏和重启。以 BASE 1、32、1024、2³² 记录接触误差、位置校正、实体数、空间访问量和 tick 时间 p95/p99，再决定是否替换默认保护。
